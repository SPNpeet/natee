## เรื่องระบบจัดการหลังบ้าน

ใบเสนอราคาระบุว่ามีระบบจัดการหลังบ้านให้ลูกค้าแก้ข้อความและรูปเองได้
เดิมทำเป็นธีม WordPress ที่มีหน้าตั้งค่าให้ลูกค้าแก้เองครบทุกจุด
ต่อมาเปลี่ยนสแตกเป็น React และ Vite ตามที่เจ้าของงานกำหนด
ซึ่งเป็นเว็บไฟล์นิ่งที่ไม่มีหน้าหลังบ้านในตัว

**ทางที่เลือกใช้** คือลูกค้าแจ้งผู้จัดทำ แล้วผู้จัดทำแก้ให้

เหตุผล เนื้อหาทั้งเว็บอยู่ในไฟล์เดียวคือ `src/data.js` แก้แล้วขึ้นเว็บใหม่ใช้เวลาไม่กี่นาที
เว็บลักษณะนี้เนื้อหาเปลี่ยนไม่บ่อย ส่วนใหญ่คือแก้ราคาและเพิ่มรูปผลงาน
การใส่ระบบหลังบ้านเข้ามาจะเพิ่มของที่ต้องดูแลและเป็นช่องโหว่ให้ต้องอัปเดตตามตลอด
โดยที่ลูกค้าอาจใช้ปีละไม่กี่ครั้ง

วิธีแก้เนื้อหาเขียนไว้ครบใน [docs/USER-MANUAL-TH.md](USER-MANUAL-TH.md) แล้ว

ถ้าภายหลังลูกค้าอยากแก้เองจริง ๆ มีสองทางที่ทำต่อได้ทันที

1. **ติดตั้ง Decap CMS** ลูกค้าเข้าหน้า `/admin` แก้เนื้อหาแล้วเว็บ build ใหม่อัตโนมัติ
   ต้องตั้งตัวยืนยันตัวตนเพิ่มหนึ่งชุด ใช้ Cloudflare Worker ได้ เป็นงานเพิ่มประมาณครึ่งวัน
2. **กลับไปใช้ธีม WordPress ที่ทำไว้แล้ว** ยังเก็บอยู่ในโฟลเดอร์ `theme/`
   มีหน้าตั้งค่าครบ 9 แท็บ พร้อมบทบาทผู้ดูแลเว็บไซต์แบบจำกัดสิทธิ์
   ทดสอบบน WordPress ของจริงผ่านครบ 45 ข้อแล้ว

## ข้อมูลที่ใช้ทำเว็บ

ข้อมูลทั้งหมดมาจากช่องทางที่เจ้าของกิจการเป็นผู้ให้ไว้เอง

- เว็บไซต์เดิมของร้าน
- เว็บไซต์ข้อมูลของร้านที่เจ้าของส่งลิงก์มาให้
- เพจ Facebook ของร้าน
- คลิปวิดีโอหน้างานจริงที่เจ้าของกิจการส่งให้ 4 ไฟล์

ประกอบด้วยชื่อร้าน คำโปรย รายการบริการ ขนาดรถ จุดเด่น 4 ข้อ ที่อยู่ เวลาให้บริการ
เบอร์โทรสองเบอร์ ลิงก์ไลน์ อีเมล รูปผลงานจริง และคลิปหน้างาน

## การตรวจสอบก่อนส่งมอบ

- `npm run build` ผ่าน ได้หน้าเว็บที่พรีเรนเดอร์แล้ว 54190 ตัวอักษร
- `npm run lint` ผ่าน ไม่มีคำเตือน
- `npm run check` ผ่านครบ 34 ข้อ ตรวจตั้งแต่เนื้อหาที่พรีเรนเดอร์ ข้อมูลโครงสร้างสำหรับ Google
  ไฟล์รูปและคลิปที่ต้องมีจริง ลิงก์ที่ชี้ไปยังของที่ไม่มีอยู่ ไปจนถึงความครบของเนื้อหาสองภาษา
  คำสั่งนี้อยู่ในขั้นตอนขึ้นเว็บด้วย ถ้าตรวจไม่ผ่านจะไม่ขึ้นเว็บให้
- ทดสอบเปิดเว็บทั้งที่รากโดเมนและใต้โฟลเดอร์ย่อย เช่น `/natee/`
  ลิงก์ไฟล์ 27 รายการเปิดได้ครบทั้งสองหน้าและทั้งสองแบบ ฟอนต์โหลดครบ ไม่มีรูปเสีย
- ขนาดที่ผู้เข้าชมโหลดครั้งแรก JavaScript 71 กิโลไบต์ รูป 33 กิโลไบต์ ฟอนต์ 88 กิโลไบต์
  รวม 10 คำขอ
- ตรวจด้วยการวัดจากหน้าเว็บจริงที่ความกว้าง 320, 375, 430, 768, 1024, 1280 และ 1440 พิกเซล
  ไม่มีเนื้อหาล้นจอในทุกความกว้าง
- ไม่มีข้อความใดเล็กกว่า 14 พิกเซล และเนื้อหาหลักอยู่ที่ 16 ถึง 18 พิกเซล
  ซึ่งเป็นขนาดที่เหมาะกับภาษาไทยมากกว่าค่ามาตรฐานของเว็บทั่วไป
- ความคมชัดของสีตัวอักษรทุกจุดผ่านมาตรฐาน WCAG ระดับ AA
- ลำดับหัวข้อถูกต้อง มี h1 เดียวและไม่มีการข้ามระดับ
- ทั้งสองภาษาแสดงเนื้อหาถูกต้อง สลับแล้วไม่มีข้อความตกค้าง
- ตัวดูผลงาน ตารางราคา คำถามที่พบบ่อย และเมนูมือถือ ทำงานครบ ไม่มี error ใน console
- คลิปหน้างานจะเริ่มโหลดเมื่อผู้เข้าชมกดดูเท่านั้น เปิดหน้าเว็บจึงโหลดแค่ภาพหน้าปก
